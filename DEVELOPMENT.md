# Development Guide — MtaaFix

Verified on: Windows 11, Java 25.0.4, Maven 3.9.16, Node 24.13.1, Flutter 3.47.1,
PostgreSQL 18.6 + PostGIS 3.6.2, Spring Boot 4.1.1 (Phase 3, 2026-10-14).

## 1. Prerequisites

| Tool | Version (verified) | Notes |
|------|--------------------|-------|
| JDK | 25 | `java -version` |
| Maven | 3.9+ | no wrapper in repo |
| Node.js | 24+ | for `web/` |
| Flutter | 3.47+ | for `mobile/` |
| PostgreSQL | 18 | local service on :5432 |
| PostGIS | 3.6.x | extension for PG18 |

No Docker / Testcontainers in this environment (decision: local PostgreSQL +
PostGIS instead).

## 2. Database setup (one-time)

1. Install PostgreSQL 18 (Windows service, port 5432).
2. Install PostGIS for PG18:
   - Download `postgis-bundle-pg18-<ver>x64.zip` from
     https://download.osgeo.org/postgis/windows/pg18/
   - Extract and copy `bin/`, `lib/`, `share/` into `C:\Program Files\PostgreSQL\18\`
     (requires administrator rights — the dependency DLLs in `bin/`
     (libgeos_c.dll, libgdal-*.dll, libproj_*.dll) must land in PG's `bin`).
3. Create the database and enable the extension:

```powershell
$env:PGPASSWORD = "<postgres-password>"
psql -U postgres -c "CREATE DATABASE mtaafix;"
psql -U postgres -d mtaafix -c "CREATE EXTENSION IF NOT EXISTS postgis;"
```

Flyway also runs `CREATE EXTENSION IF NOT EXISTS postgis` in V1, but the
executing role must be able to create extensions (superuser or the extension
pre-installed as above).

## 3. Configuration

Copy `.env.example` (repo root) and export as environment variables (no loader
script — set them in your shell or IDE run configuration):

| Variable | Purpose | Local default |
|----------|---------|---------------|
| `SERVER_PORT` | HTTP port | 8080 |
| `SPRING_DATASOURCE_URL` | JDBC URL | `jdbc:postgresql://localhost:5432/mtaafix?currentSchema=public&ssl=false` |
| `SPRING_DATASOURCE_USERNAME` | DB user | `postgres` |
| `SPRING_DATASOURCE_PASSWORD` | DB password | `change-me` (set yours) |
| `SPRING_FLYWAY_ENABLED` | run migrations on boot | `true` |
| `JWT_SECRET` | HS256 secret, min 32 chars | dev placeholder |
| `CORS_ALLOWED_ORIGINS` | web dev origin | `http://localhost:5173` |

Profiles:
- default → PostgreSQL (+ Flyway, `ddl-auto: validate`)
- `dev` → same as default (explicit local alias)
- `test` → H2 in-memory, `ddl-auto: create-drop`, Flyway **disabled**
  (used by unit/context tests; geometry/jsonb DDL warnings on H2 are expected
  and non-fatal — spatial behavior is verified on PostgreSQL instead)

## 4. Backend

```powershell
# run (from repo root)
$env:SPRING_DATASOURCE_PASSWORD = "<your-password>"
$env:JWT_SECRET = "<32+ char secret>"
mvn -f backend/pom.xml spring-boot:run

# unit + export tests (no database needed; H2)
mvn -f backend/pom.xml test

# full matrix including PostgreSQL+PostGIS integration tests
$env:MTAAFIX_PG_IT = "true"
mvn -f backend/pom.xml test
```

- Health: `GET http://localhost:8080/actuator/health`
- Swagger UI / OpenAPI: restricted to `ADMINISTRATOR` role
  (`/swagger-ui.html`, `/v3/api-docs`).
- Exported spec (committed): `docs/api/openapi.json` — regenerated by
  `OpenApiExportTest` on every `mvn test` run.

### Test matrix

| Suite | Trigger | Database | What it proves |
|-------|---------|----------|----------------|
| `MtaaFixApplicationTests` | always | H2 (test profile) | Spring context boots |
| `OpenApiExportTest` | always | H2 (test profile) | springdoc spec generates; writes `docs/api/openapi.json` |
| `PostgresIntegrationTest` | `MTAAFIX_PG_IT=true` | local PostgreSQL+PostGIS | Flyway applied; PostGIS 3.x available; geometry round-trip (insert + `ST_AsText`) |

Integration tests are `@Transactional` (rolled back) and create throwaway rows.

## 7. Troubleshooting

| Symptom | Cause / fix |
|---------|-------------|
| `could not load library ".../postgis-3.dll"` | GDAL/GEOS/PROJ DLLs missing from PG `bin` — re-copy the PostGIS bundle `bin/` with admin rights |
| Port 8080 already in use | another service owns the port — run with `SERVER_PORT=8085` |
| Flyway does nothing on boot | Spring Boot 4 requires the `spring-boot-flyway` module (already in `pom.xml`) |
| H2 DDL warnings about geometry/jsonb | expected — test profile only; spatial types are PostgreSQL-only |
| `PostgresIntegrationTest` skipped | normal without `MTAAFIX_PG_IT=true` |

## 8. CI

`.github/workflows/ci.yml` runs on push/PR to `master` (plus manual
`workflow_dispatch`) with four parallel jobs:

- **backend** - `mvn test`: full H2 suite plus PostgreSQL+PostGIS
  integration tests (`MTAAFIX_PG_IT=true`) against a
  `postgis/postgis:18-3.6` service container (`JWT_SECRET` is set to a
  >=32-char CI value for the default-profile IT context)
- **web** - `npm run lint && npm run test && npm run build`
- **mobile** - `flutter analyze` + `flutter test`
- **secrets** - gitleaks scan over full history

`.github/workflows/release.yml` runs on tags `v*`: packages the jar
(tests re-run) and the web bundle, attaching `mtaafix-*.jar` +
`web-dist.zip` to the GitHub Release.

Local PostgreSQL IT (developer machine):

```bash
set MTAAFIX_PG_IT=true
set SPRING_DATASOURCE_PASSWORD=<local db password>
set JWT_SECRET=<32+-char value for the default profile>
mvn -B -f backend/pom.xml test
```
